# 医疗字幕自动化流水线 — 开发计划

## 1. 项目概述

### 1.1 要解决的问题

给时长1小时以上的医疗教学视频校对字幕，纯人工操作极其繁琐。现有流程需要手动：运行ASR → 逐句校对医学术语 → 导入达芬奇 → 叠加字幕 → 渲染导出。每次处理需要数小时。

### 1.2 目标

一个面向**小白用户**的本地Web面板：拖入视频+课程PDF，点击开始，等待全流程自动完成，得到带术语校正字幕的成品视频。

### 1.3 核心流水线

```
视频文件 ──→ 在线ASR ──→ SRT字幕 ──→ LLM+PDF术语校正 ──→ 达芬奇导入 ──→ 自动导出
              (双引擎)                  (映射表批量替换)      (MCP自动化)     (渲染队列)
```

## 3. 技术决策记录

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 触发方式 | 本地Web面板 | 小白用户友好，拖拽操作，进度可视化 |
| ASR策略 | 双引擎（必剪/剪映），用户选择 | 互为备选，必剪零依赖、剪映准确率更高 |
| 术语校正 | LLM先建立映射表，再批量替换 | 比逐句问LLM更可靠、更经济、可审计 |
| PDF解析 | MinerU (opendatalab) | 文本+图片PDF通吃，OCR引擎兜底，输出结构化Markdown/JSON |
| 达芬奇集成 | 通过MCP Server自动化 | 已有davinci-resolve-mcp可用，34个复合工具 |
| LLM接口 | OpenAI兼容API | VideoCaptioner已有完整链路，直接复用 |
| Web框架 | FastAPI + 静态前端 | 轻量、异步友好、和Python生态一致 |
| 进度通信 | SSE (Server-Sent Events) | 单向推送进度，实现简单，浏览器原生支持 |

## 4. 模块拆解

### 4.1 Web面板（Phase 1）

```
功能:
  - 视频文件拖拽/选择上传
  - PDF课程文件拖拽/选择上传
  - ASR引擎二选一（必剪 / 剪映）
  - 全流程进度条（分步骤状态）
  - 成品视频下载

技术:
  - FastAPI (后端API)
  - 单页HTML + vanilla JS / htmx (前端)
  - SSE推送进度更新
  - 复用 davinci-resolve-mcp 的控制面板风格
```

### 4.2 术语映射校正模块（Phase 2）

```
流程:
  1. MinerU解析PDF → 结构化Markdown/JSON
     - 支持文本型PDF + 纯图片型PDF（OCR引擎自动切换）
     - 自动去除页眉页脚、处理多栏排版
     - 表格→HTML、公式→LaTeX
     - 输出按阅读顺序排列的结构化文本
  2. LLM从结构化文本中识别医学术语
     （输出JSON: {"术语": "英文/标准中文", "常见错误": ["错1","错2"]}）
  3. 构建术语映射表 (正确术语 ← 所有常见错误形式)
  4. 遍历SRT每句，应用映射表替换
  5. 输出校正后的SRT

关键设计点:
  - 映射表是可以人工审核和编辑的（JSON文件，用户在跑全流程前可检查）
  - 校正日志记录每次替换（方便追溯）
  - LLM prompt需要明确输出格式约束
```

### 4.3 达芬奇自动化模块（Phase 3）

```
流程:
  1. MCP: 检查Resolve连接状态
  2. MCP: 获取/创建项目
  3. MCP: 导入视频到Media Pool
  4. MCP: 创建时间线，视频放入轨道
  5. MCP: 导入校正后SRT作为字幕轨道
  6. MCP: 配置渲染设置（基于视频参数）
  7. MCP: 加入渲染队列并执行
  8. 轮询渲染状态直到完成

依赖:
  - davinci-resolve-mcp server 已安装并运行
  - Resolve Studio 需处于运行状态
  - 外部脚本设置为Local
```

### 4.4 Pipeline编排器（贯穿）

```
Pipeline Orchestrator职责:
  - 串联全部步骤，管理状态机
  - 每步开始/完成/失败时推送SSE事件
  - 步骤间数据传递（SRT文件、校正后SRT、渲染输出路径）
  - 错误处理和重试策略
  - 临时文件管理

状态机:
  IDLE → ASR_RUNNING → ASR_DONE
       → TERM_EXTRACTING → TERM_MAPPING → TERM_CORRECTING → TERM_DONE
       → RESOLVE_IMPORTING → RESOLVE_RENDERING → RESOLVE_DONE
       → COMPLETE

  任一步骤失败 → FAILED (可查看错误日志，支持从失败步骤重试)
```

## 8. 关键风险

| 风险 | 影响 | 应对 |
|------|------|------|
| PDF提取不完整（表格/图片中的术语） | 术语映射表缺失 | 已解决：MinerU OCR引擎处理图片PDF，输出结构化文本 |
| LLM术语识别不准确 | 校正质量下降 | 映射表可编辑；支持多轮确认 |
| 达芬奇MCP长时间渲染不稳定 | 流程中断 | 从失败步骤重试；渲染轮询+超时处理 |
| 在线ASR接口变更 | ASR步骤不可用 | 双引擎互为备份 |
| 1h+视频ASR耗时过长 | 用户体验差 | 异步处理；展示预估时间；支持后台运行 |

## 9. 开发约定

- 后端Python，Web面板前端使用单个HTML文件（零构建工具）
- 所有步骤输出结构化日志，便于调试和状态展示
- 映射表格式：JSON，可读可编辑
- 临时文件统一管理在 `work/` 目录，完成后可清理
- 进度推送使用SSE，事件格式：`{step, status, progress_pct, message, data?}`
