# 医疗字幕自动化业务流程文档

本文档记录 DRautocut 面向生产使用的业务流程、用户交互规则和关键处理策略。它是后续开发的产品逻辑基准线；代码实现、UI 改动和恢复机制应尽量与本文档保持一致。

## 1. 业务目标

DRautocut 要解决的是长时长医疗课程视频字幕校对和导出的重复劳动。

目标用户只需要准备：

- 剪好的课程视频
- 与课程相关的 PDF 课件或讲义
- 可用的 ASR 引擎和 LLM 配置
- DaVinci Resolve 输出预设和字幕样式模板

系统自动完成：

- 视频转写为初版 SRT
- 从 PDF 中提取候选课程术语替换表，并让用户先确认
- 自动应用术语替换
- 优化过长、过短字幕的断句
- 清理不需要的标点
- 导入 DaVinci Resolve
- 使用指定字幕样式和输出预设渲染成片

最终交付物包括：

- 渲染后视频
- 最终 SRT
- 初版 ASR SRT
- 术语替换表
- 术语替换执行报告
- 字幕优化报告
- 完整任务日志

## 2. 总体流程

```text
视频 + PDF
  -> 视频探测
  -> PDF 提取课程术语表
  -> 用户审核/修改/确认课程术语表
  -> 音频提取
  -> ASR 转写
  -> 合并初版 SRT
  -> ASR 分段切点三句窗口语义修复（最高优先级）
  -> 脚本清理标点、语气词和基础单位写法
  -> LLM 强制处理过长字幕
  -> 应用课程术语表替换
  -> 医疗知识库规则归一化
  -> LLM 全量术语审校，并顺带返回语义断句建议
  -> 导入 Resolve
  -> 应用模板字幕样式
  -> 使用输出预设渲染
  -> 保存最终产物和报告
```

业务上将流程分为三个层次：

- 主流程：从视频/PDF 到最终视频，尽量不中断。
- 可恢复流程：ASR、术语映射、字幕优化、渲染失败后可以从已有产物继续。
- 二次矫正流程：用户针对最终字幕做小范围纠错，不重新跑完整流程。

## 3. 用户操作模型

### 3.0 Web 面板开箱感知

当前开发形态先保持 WebUI，但 Web 面板必须按照未来桌面 App 的“小白用户开箱体验”设计。用户打开页面后，不应先上传文件、点击开始、等待失败，才知道缺少什么环境。

Web 面板主导航采用“左侧大步骤 + 顶部子步骤 + 中央工作区”的应用式布局。左侧大步骤从上到下固定为：

1. 环境检查：展示本机依赖状态，提供查漏补缺、下载、修复、重试等入口。
2. 配置填写：填写 LLM 连接，测试连接，设置产出目录、知识库目录和默认导出偏好。
3. 知识库：面向通用 LLM 字幕校正应用，不局限医疗；用户可查看、切换、导入 PDF、维护术语分类和单位/格式规则。
4. 新建任务：上传视频/PDF，选择 ASR、字幕参数、输出方式；开始后进入处理进度，直到 SRT 或成片完成。
5. 历史任务：按完成时间倒序展示最近完成任务；提供批量替换字幕并重新输出的入口。

选中左侧大步骤后，顶部 tab 显示该大步骤内的子步骤；中央区域只显示当前子步骤的主要交互界面。

布局策略必须优先保证普通用户“一屏看懂当前页”：

- 新建任务页采用 3 个主操作卡片加 1 个横向输出/开始卡片，保证每个卡片有足够阅读宽度，同时避免一个长表单向下堆叠。
- 历史任务不使用无限长列表；默认按完成时间倒序分页展示，底部提供 `1 2 3 4` 形式页码和上一页/下一页。历史列表过长时只允许列表内部滚动，不能把左侧状态栏或顶部导航挤出视口。
- 新建任务和历史任务属于高频主工作区，不应显得过矮；在不产生整页溢出的前提下，卡片和列表应尽量占用中央可用高度，让页面看起来稳定、充实。
- 后续新增页面时，超过一屏的信息优先拆成子 tab、分页、折叠高级设置或局部滚动列表，不把主要操作按钮推到页面底部。
- 品牌副标题使用面向普通用户的“老司机字幕助手”，不使用偏技术化的内部描述。

Web 面板业务流固定为：

```text
环境状态
  -> 配置填写
  -> 知识库选择/维护
  -> 新建任务
  -> PDF 术语预检
  -> 课程术语确认
  -> ASR / 术语校正 / 字幕优化 / 导出
  -> 结果查看
  -> 历史任务 / 批量替换字幕
```

界面必须是状态驱动的向导式任务流。主区域同一时间只呈现当前用户应该处理的事情：

- 新建任务：准备视频、PDF、ASR、输出模式和模型连接。
- PDF 术语预检：显示术语提取进度。
- 课程术语确认：阻塞式主页面，用户确认、修改或终止后才继续。
- 处理中：显示全局进度、当前阶段、阶段进度和日志摘要。
- 完成或失败：显示结果、失败原因和可恢复入口。
- 历史任务：展示最近完成任务；批量替换字幕后自动进入既有输出流程。

“从上次继续”不作为普通用户主入口常驻展示。未完成任务恢复属于后续高级/诊断能力，当前历史任务主界面优先展示已完成任务和批量替换字幕。

知识库需要区分三类内容：

- 通用领域知识库：例如医疗、法律、财经、教育等，可跨项目复用。
- 规则库：单位、大小写、数字格式、专有写法、固定替换模式等确定性规范，应有独立分类和启用状态。
- 本次任务专名表：人名、学校名、医院名、课程编号、项目编号等强上下文信息，默认服务于第 4 阶段任务校正，不自动进入通用知识库；是否入库需要用户显式确认。

专业单位和特定写法要求优先放在知识库的“规则库/格式规范”子页，而不是混在普通术语表里。普通术语表解决“词是什么”，规则库解决“遇到这种格式应怎么写”。

Web 面板首页必须展示系统状态中心：

- 后端服务是否运行
- 当前任务是否空闲、运行中、等待术语确认、失败或已完成
- FFmpeg/FFprobe 是否可用
- DaVinci Resolve 相关模板和脚本环境是否可用
- 必剪在线 ASR 是否可用
- 本地 ASR 环境是否准备好
- 本地模型是否完整
- LLM 当前配置是否可连接
- 当前医疗知识库是否存在、条目数量和更新时间
- 工作目录、输出目录、日志目录是否可写

状态展示必须面向非技术用户，使用“可用、未配置、缺失、可修复、需要手动处理”这类可理解状态。错误信息必须给出下一步动作，例如“请先启动 LM Studio 本地服务”或“请填写 API Key 并点击测试连接”。

LLM 配置区必须提供“测试连接”按钮。用户填写 `model`、`base_url` 和 `api_key` 后，可以立即得到成功或失败反馈。对于 `http://127.0.0.1:1234` 这类本地模型服务地址，系统应明确说明这是 API 地址，不是医疗字幕 App 页面；医疗字幕 App 页面使用 Web 面板自己的地址。

模型下载和环境修复必须是用户主动点击的动作。普通状态刷新不能静默安装依赖、下载模型或修改用户文件。

对于默认会返回 `reasoning_content` 的思考模型，生产流程中的结构化 JSON 任务应优先关闭 thinking mode。术语表提取和字幕断句优化都要求模型返回可解析 JSON；如果只返回思考内容而没有最终答案，系统不能把整段思考内容当作成功结果，应提示模型连接/模式配置问题或自动使用已知的关闭 thinking 参数。

术语表预检还必须控制输出长度。PDF 阶段只需要少而准的候选，不需要穷尽课程里所有名词；单次术语预检默认最多输出 8 条高价值候选，优先人名、学校/医院/机构名、课程强相关专名、罕见或易错医学缩写。模型调用必须给足 JSON 输出余量，避免因为 token 上限截断导致半截 JSON。

医疗知识库在当前版本只提供状态查看入口，不提供完整编辑后台。界面应明确区分：

- 本课程术语表：本次 PDF 生成并由用户确认，允许包含人名、学校名、医院名、机构名、讲者姓名、项目名和课程名。
- 医疗知识库：跨课程复用的稳定医学知识，不接收强课程相关的人名、学校名、机构名等内容。

### 3.1 新任务

用户在 Web 面板中上传视频和 PDF，选择 ASR 方式、LLM 配置和必要的处理选项，然后点击开始。

点击开始前，系统必须做前置验收。

阻断条件包括：

- 没有选择视频
- 当前 ASR 引擎不可用
- LLM 未配置或测试失败
- 工作目录不可写
- 选择本地 ASR 但模型或运行环境不完整

非阻断警告包括：

- 没有上传 PDF
- Resolve 不可用但用户只想先生成 SRT
- 本地 ASR 不可用但必剪在线 ASR 可用

用户应能选择“只生成 SRT”。该模式会完成 ASR、术语/格式应用、字幕优化和报告生成，但不会连接 DaVinci Resolve，也不会导入时间线或渲染视频。它用于：

- 用户暂时没有安装或打开 Resolve
- 用户只想先检查字幕质量
- 长视频先做字幕生产，再择机渲染
- 排查 ASR/LLM/术语问题时缩短反馈链路

任务开始后，Web 面板必须展示：

- 全局进度条
- 当前大阶段
- 可见的阶段日志
- 长耗时步骤的局部进度
- 失败原因和可恢复入口

全局进度条表示整条主流程完成度。它应该单向增长，不因为某个阶段内部重试、日志回放或阶段切换而倒退。

### 3.2 从上次结果继续

如果任务已经生成可用 SRT，但后续步骤失败，用户应能从已有 SRT 继续，而不是重新跑 ASR。

典型恢复入口：

- 从初版 ASR SRT 继续：跳过 ASR，重新做术语映射、术语替换、字幕优化和导出。
- 从规则归一化后 SRT 继续：跳过 ASR、课程术语替换和规则归一化，重新做 LLM 术语审校、字幕优化和导出。
- 从最终 SRT 继续：跳过文本处理，只重新导入 Resolve 和渲染。

恢复任务应创建新的运行记录，避免旧失败日志继续污染当前进度。

### 3.3 二次矫正

二次矫正是生产流程中用户对最终字幕做小范围修订的入口，不等同于重新跑主流程。

默认策略：

- 用户修改术语表或新增替换项后，直接作用于当前最终 SRT。
- 不重新跑完整字幕优化。
- 只检查被替换影响到的字幕。
- 如果受影响字幕出现过长或过短，再做局部窗口优化。
- 如果没有长度异常，直接生成新的最终 SRT。

二次矫正之后，用户可以选择只导出 SRT，或重新导入 Resolve 渲染视频。

## 4. ASR 阶段

### 4.1 输入

- 视频文件
- 用户选择的 ASR 引擎
- 是否启用长视频分段
- 分段时长
- 并发数

### 4.2 输出

- 初版 SRT
- ASR 日志
- 如果启用分段，则保存每段的转写状态和合并结果

### 4.3 长视频策略

生产视频通常接近或超过 1 小时，在线 ASR 还可能存在每日额度限制。因此长视频应优先支持分段转写。

推荐策略：

- 默认目标分段约 10 分钟。
- 优先在接近目标位置的静音处切分。
- 每段记录起止时间和 offset。
- 每段独立提交 ASR。
- 每段返回后将时间轴平移回全片时间。
- 最后合并为完整初版 SRT。

### 4.3.1 ASR 分段切点修复

分段 ASR 的切点附近容易出现句子被截断、上下句语义粘连或断句不自然的问题。合并初版 SRT 后，应在进入课程术语替换之前增加一个轻量 LLM 修复步骤。

处理策略：

- 只处理真实分段切点附近的小窗口，不全量处理字幕。
- 对每个切点，优先定位切点前最后一条字幕作为“当前字幕”。
- 将“当前字幕”的前一条、当前字幕、切点后一条共三条字幕发给 LLM。
- LLM 只允许在三条字幕的原始文字范围内做语义断句和边界重排。
- LLM 不允许新增、删除、改写医学事实或术语。
- 系统校验三条字幕合并后的总内容必须保持一致；校验失败则保留原窗口。
- 通过校验后，脚本按原三条字幕的总时间范围重新分配时间戳，并写入边界修复报告。

该阶段不同于后续短字幕/长字幕优化。它的目标是修复 ASR 分段造成的边界问题，发生在术语替换和全量 LLM 术语审校之前。

### 4.4 并发策略

在线 ASR 的并发应保守。

- 默认并发为 1。
- 用户可以尝试设置为 2。
- 不建议默认更高，避免触发接口限制或失败率上升。
- 失败段应能单独重试。

本地 ASR 后续接入后，可根据 CPU/GPU 资源再设计更高并发。

### 4.4.1 ASR 引擎可用性

当前产品形态切换为在线 ASR 优先：

- WebUI 使用下拉菜单展示 ASR 在线接口。
- 必剪作为当前基线在线 ASR；外部参考项目中重复的 B 接口不重复搬运。
- 新搬运接口必须记录是否需要签名服务、Cookie、登录态或外部密钥。
- 接口测试结果必须标记为“无需凭证可跑通”“需要凭证/签名服务”“接口不可用或待确认”之一。
- 本地 ASR 暂时下线；WebUI 不展示模型下载、环境准备、本地模型状态或本地 ASR 选项，主流程也不保留 `local` 引擎分支。

ASR 引擎选择必须由状态驱动：

- 必剪：作为当前可用在线 ASR，显示可用性和失败原因。
- 其他在线接口：必须有明确的配置项、失败原因和最小样例测试结果，才允许在下拉菜单中开放。
- 剪映：在签名服务没有稳定方案前显示为不可用，并提示需要配置 `JIANYING_SIGN_SERVICE_URL`。
- 快手：已搬运但接口侧返回禁用时，显示为不可用，不允许启动任务。

AsrTools 接口和 SRT 优化流程审阅结论记录在 [asrtools-review.md](/Users/x/Work/Code/DRautocut/docs/asrtools-review.md)。

以下本地 ASR 内容仅保留为历史验证记录，不作为当前 WebUI 和主流程要求。

本地 ASR 第一阶段目标是接入 Qwen3-ASR。模型不内置在应用中，缺失时由 Web 面板模型管理入口下载。模型下载需要显示进度、失败原因和重试入口。

本地 ASR 运行环境也必须由 Web 面板管理。环境准备规则：

- 状态刷新只检测环境，不自动安装。
- 用户点击“准备本地 ASR 环境”后，系统才创建独立 Python 环境。
- 独立环境不得污染系统 Python。
- 安装日志必须保存，失败时显示可理解原因。
- 安装完成后必须重新检测 `qwen_asr`、`torch` 和模型文件。
- 运行环境和模型完整只代表“本地 ASR 基础资源就绪”。在真正接入 Qwen3-ASR 转写适配器之前，界面必须继续禁止选择本地 ASR，并明确提示“环境和模型已就绪，转写适配器待接入”。
- 当基础资源就绪但适配器未接入时，状态应显示为“需处理/待接入”，不能显示“缺失”，避免用户误以为模型或环境仍未安装。
- 只有完成本地转写适配器开发，并通过短视频端到端验证后，本地 ASR 才能在界面中选择。
- 如果安装耗时较长，界面必须显示正在准备、最近日志、失败原因和重试入口。

本地 ASR 适配器 MVP 边界：

- 使用独立 Python 环境运行 `qwen_asr`，主 Web 后端不直接导入模型包。
- 使用 `Qwen3-ASR-1.7B` 生成文本，使用 `Qwen3-ForcedAligner-0.6B` 生成时间戳。
- 输出标准 SRT，后续继续复用现有术语校正、短字幕/长字幕优化、去标点、SRT-only/达芬奇流程。
- MVP 先验证短视频整段转写，再进入本地分段长视频转写。
- 适配器通过短视频冒烟测试后，Web 面板才允许用户选择“本地 ASR”。
- 当前实现通过了 3 分钟短视频 SRT-only 冒烟测试，可以作为本地 ASR MVP 入口开放。
- 本地长视频模式复用统一分段规划：先探测时长、检测静音、按目标时长切段、抽取音频段。
- 本地分段转写必须一次加载模型，然后逐段转写，不能每段重复加载模型。
- 本地分段模式当前按顺序执行；并发会带来显存/内存放大，暂不默认启用。
- 本地分段进度应显示总段数、当前段、已完成段、失败段和整体百分比。
- 当前本地 ASR 每次任务会重新加载模型；模型常驻服务、任务取消和失败段单独重试属于下一阶段优化。

生产样例验证记录：

- 58 分 58 秒医疗课程视频已完成本地分段 ASR SRT-only 验证。
- 分段数：6 段，每段约 10 分钟，最后一段约 8 分 54 秒。
- 6 段全部成功，无失败段。
- ASR 段转写总耗时约 753 秒，不含前处理约 12.5 分钟。
- 输出 SRT 共 667 条字幕，时间轴单调，尾部覆盖到 58:57.758。
- 观察到内存峰值约 12GB；当前机器可跑通，但后续应在 Web 面板提示本地 ASR 会占用较多内存。

### 4.5 进度展示

ASR 不能让用户长时间只看到“运行中”。

最低要求：

- 整体 ASR 阶段有进度。
- 分段模式下显示当前段、总段数、成功段、失败段。
- 单段失败时显示具体错误。
- 所有段失败时任务失败。
- 部分段失败时应进入可恢复或可重试状态，而不是静默继续生成不完整字幕。

## 5. 术语映射阶段

### 5.1 业务目标

术语映射阶段发生在 ASR 之前。它不是让 LLM 逐句改字幕，而是让 LLM 先基于 PDF 课件和课程文件名等元信息生成一份可审计、可复用、可二次编辑的课程术语表。

替换表的重点是：

- 人名
- 地名
- 学校名
- 医院名
- 机构名
- 指南名
- 药品名
- 检查项目
- 手术或治疗方式
- 医学缩写
- 罕见或冷门专业词
- 可能被 ASR 误识别的别名或同音错误

不应大量收录：

- 过于常见的学科基础词
- LLM 没有把握的猜测项
- PDF 中出现但非常普通、不影响校对的术语

LLM 可以调动医学领域常识辅助判断，但输出必须尽量高置信、少而准。由于此阶段还没有初版 ASR，术语表应偏向“标准术语 + 可能错误别名”，而不是依赖字幕中的实际错词。

### 5.1.1 课程术语表与医疗知识库边界

术语资产分为两层：

- 当次课程术语表：服务于当前视频、当前 PDF、当前课程或同一课程系列。
- 医疗知识库：服务于跨课程、跨项目复用的稳定医学知识。

人名、地名、学校名、医院名、机构名、讲者姓名、项目名称、课程名称等强课程相关信息，只进入当次课程术语表或同一课程系列的复用术语表，不进入医疗知识库。

原因：

- 这类信息通常只对当前课程有效。
- 跨项目复用容易造成误替换，例如把别的课程中的同音人名误改成当前讲者姓名。
- 医疗知识库应保持领域稳定性，避免被具体课程、讲者和机构污染。

医疗知识库可以沉淀：

- 稳定医学单位和格式规则，例如 `mmHg`。
- 药物名、术式名、检查项目、指南名等跨课程稳定术语。
- 常见 ASR 易错医学缩写和标准大小写。
- 已经过多课程验证的安全替换模式。

医疗知识库沉淀策略：

- 用户确认课程术语表后，系统应从确认项中筛选可跨课程复用的稳定医学术语，写入跨课程医疗知识库。
- 人名、地名、学校名、医院名、机构名、讲者姓名、项目名、课程名等强课程相关项必须过滤，不写入医疗知识库。
- 写入知识库时按 `wrong + correct` 去重；重复出现时只更新来源、次数和最后更新时间。
- 没有 `evidence`、`note`、`aliases`、`patterns` 等依据的历史替换项不得自动入库，避免早期测试或低置信替换污染知识库。
- 知识库状态面板显示的是跨课程医疗知识库条目数，不包含本课程术语表条目数。
- 如果当次确认项全部是人名或机构名，知识库条目数不增加，这是符合预期的。

当次课程术语表可以沉淀：

- 讲者姓名、人名、学校名、医院名、机构名。
- 当前课程 PDF 中出现的专有项目名或课程名。
- 当前课程独有、但不适合跨课程复用的别名和误识别写法。

### 5.2 输入

- PDF 提取文本
- PDF 文件名、视频文件名和课程标题等课程元信息
- LLM 配置
- 可选用户提示词

### 5.3 输出

- 原始 LLM 课程术语表
- 用户确认后的课程术语表
- 术语映射阶段日志

### 5.4 分块策略

PDF 内容可能较长，不应一次性无限制丢给 LLM。

推荐策略：

- PDF 正文和课程元信息先压缩为有限上下文。
- 按 PDF 文本块生成候选标准术语。
- 文件名、课程标题中的讲者姓名、课程名、机构名如果没有出现在 PDF 正文中，也应作为当次课程术语表候选来源。
- 合并去重。
- 优先输出“标准写法”和“可能 ASR 错写/别名”。
- 失败时允许重试。
- PDF-first 阶段必须做安全过滤：`correct` 必须能在 PDF 文本中找到；如果 `wrong` 本身已经出现在 PDF 文本中，不能直接丢弃，应保留给用户确认，并标记为“PDF 中也出现该写法”。医学旧称、同义说法、ASR 易错词经常会同时出现在 PDF 或字幕上下文中，直接过滤会导致术语确认页只剩人名。
- 被过滤的候选应保存在 `dropped_replacements` 中，并记录过滤原因，便于后续调试提示词。

当前真实 PDF 验证记录：

- 使用生产 PDF 和本地 `qwen/qwen3-4b`，上下文 6000 字，约 29 秒完成术语预检。
- 过滤前模型会生成危险候选，例如概念替换 `高血压危象 -> 高血压急症` 和 PDF 中不存在的错误写法。
- 安全过滤后保留 `陈欣 -> 陈歆` 这类 PDF 支撑的人名候选。
- 本轮过滤掉 4 条高风险候选，保留 1 条可审核候选。

### 5.5 术语确认关口

术语表生成后，生产流程默认进入用户确认关口。

原因：

- LLM 生成的替换表可能包含危险误替换。
- 用户需要在 ASR 和全量纠错前看到候选术语。
- 用户发现明显问题时，应能及时终止任务。
- 用户应能修改、禁用或新增替换项，再继续后续纠错链路。

生产默认行为：

- PDF 术语表生成后暂停主流程。
- Web 面板展示完整术语替换表。
- Web 面板同时展示候选数量和已安全过滤的高风险候选数量。
- 每条替换默认启用，但用户可以取消启用。
- 用户可以修改错误词/别名和正确词。
- 用户可以选择“确认并继续”。
- 用户可以选择“终止任务”，保留上传文件和原始术语表。
- 用户确认后保存一份确认版术语表，再开始 ASR 和后续 LLM 字幕纠错/断句流程。
- 术语确认后继续主流程时，必须保留用户在开始任务时选择的 ASR 引擎、分段开关、分段时长、最大分段时长、并发数和 SRT-only 设置。

自动确认只能作为可选批处理模式，不能作为生产默认。

### 5.6 LLM 执行策略

长任务中的 LLM 调用必须按小任务执行，不能把完整 SRT 或完整 PDF 不受控地一次性丢给模型。

规则：

- PDF 术语提取按文本块压缩、候选生成、合并去重执行。
- 字幕纠错和断句按问题窗口执行，而不是全量字幕一次性处理。
- 每个 LLM 子任务都要有超时、重试、失败兜底和进度事件。
- 本地模型和在线模型使用同一业务接口，但允许不同的上下文长度和超时配置。
- 本地 Qwen 系列模型必须显式禁用 thinking，例如在用户提示末尾追加 `/no_think`，否则可能长时间只返回 `reasoning_content` 而没有最终 JSON。
- LLM 输出必须经过结构化校验；校验失败时不能直接污染最终 SRT。
- 批量处理时要保存中间结果，任务中断后能从已完成块继续。

## 6. 课程术语替换与规则归一化阶段

### 6.1 业务目标

本阶段包含两层确定性处理：

1. 课程术语替换：将用户确认后的本课程术语表应用到 SRT 中，修正 ASR 对人名、机构名、课程专有词、专业术语的错误识别。
2. 医疗知识库规则归一化：从跨课程医疗知识库或内置规则库读取稳定规则，对单位、英文缩写、数字单位组合、固定医学格式做规范化。

这两层都属于脚本执行的确定性处理，不依赖 LLM 做语义猜测。

本阶段必须可审计：

- 每个替换项命中了几次
- 改了哪些字幕
- 修改前后文本是什么
- 哪些确认过的替换项没有命中
- 哪些医疗知识库规则被触发

### 6.2 替换可靠性

简单字符串替换不足以满足生产需求。课程术语和规则归一化都需要支持多种变体。例如同一个稳定单位规则可能在字幕中表现为：

- `180 mmHg`
- `180mmhg`
- `180 mm Hg`
- `180毫米汞柱`
- `一百八十毫米汞柱`
- 换行或空格插入后的变体

因此替换表需要支持：

- `wrong`：主要错误写法
- `correct`：标准写法
- `aliases`：其他错误写法或同义变体
- `patterns`：安全正则，用于单位、大小写、空格差异等场景
- `note`：说明
- `confidence`：置信度
- `evidence`：证据

替换执行时应优先做保守、安全的匹配，避免把正常句子误改。

### 6.3 医疗知识库规则归一化

医疗知识库规则归一化不等于某一个单位替换。它是一层可扩展的确定性规则系统，后续应从医疗知识库中读取跨课程稳定规则。

规则类型可以包括：

- 医学单位：血压、浓度、剂量、体温、检验指标单位等。
- 英文缩写：大小写、空格和常见错写归一。
- 数字单位组合：数字、中文数字、单位之间的标准格式。
- 药物名、检查名和常见医学名词：音近误识别、旧称和标准名归一。
- 固定医学格式：指南名、分级分期、检查项目缩写等稳定写法。

`mmHg` 只是当前已验证的一条血压单位规则示例，不是阶段名称。比如血压单位规则可以稳定标准化：

- `180 mm 汞柱` -> `180mmHg`
- `180 mmHg` -> `180mmHg`
- `120 mm 汞柱` -> `120mmHg`
- `180或120 mm 汞柱` -> `180/120mmHg`
- `一百八十毫米汞柱` -> `180mmHg`
- `一百八十或一百二十毫米汞柱` -> `180/120mmHg`
- `二百一百一十毫米汞柱` -> `200/110mmHg`

这类规则属于确定性格式归一化，应该在规则归一化阶段执行，并写入规则命中报告。LLM 可以提出候选术语，但不能成为稳定格式规则的唯一来源。

规则归一化必须保守：

- 只能匹配明确的模式。
- 不能跨字幕换行拼接医学数值。
- 对容易误判的连续中文数字只处理窄场景，例如血压对只处理含两个 `百` 的场景，避免把 `一百八十毫米汞柱` 误拆成 `100/80mmHg`。
- 每次命中都要写入替换报告，`matched_by` 标记为内置规则来源。
- 如果同一药物名、单位或检查名在相邻字幕或全篇中出现“一处正确、一处错误”，优先补充确定性归一规则或知识库规则，而不是只依赖 LLM 局部修正。

当前真实样例验证记录：

- 58 分 58 秒生产样例的初版本地 ASR SRT 中，原始 `毫米汞柱` 出现 29 次。
- 内置规则标准化后，`毫米汞柱` 剩余 0 次，`mmHg` 出现 29 次。
- 检测到 0 个跨行误匹配。
- 其中 1 条 ASR 连续中文血压对 `二百一百一十毫米汞柱` 被标准化为 `200/110mmHg`。

### 6.4 未命中处理

如果用户确认过的替换项没有实际命中，应记录到报告中。

未命中不一定是错误，可能表示：

- ASR 实际没有识别成该错误词
- 错误词存在空格、大小写或单位变体
- 字幕优化后文本已经变化
- 术语项来自 PDF，但字幕中没有出现

Web 面板应在二次矫正中提示这些未命中项，方便用户决定是否新增 alias 或 pattern。

## 7. LLM 术语审校阶段

### 7.1 业务目标

PDF 课程术语表、课程术语替换和医疗知识库规则归一化只能覆盖已知映射与稳定规则。生产 ASR 仍可能出现大量没有被前两层命中的医学术语错误，因此需要增加一个全量分批的 LLM 术语审校阶段。

该阶段发生在课程术语替换与规则归一化之后、字幕断句优化之前：

```text
课程术语替换与规则归一化后 SRT
  -> LLM 分批审校医学术语
  -> 脚本应用高置信补丁
  -> 字幕断句优化
```

### 7.2 补丁式输出

LLM 不允许直接返回完整 SRT，也不允许自由改写整段字幕。它只能返回结构化补丁：

```json
{
  "patches": [
    {
      "cue": 123,
      "old": "字幕中的原文片段",
      "new": "修正后的片段",
      "reason": "医学术语、人名、单位或缩写修正依据",
      "confidence": "high"
    }
  ]
}
```

脚本应用补丁时必须满足：

- `cue` 必须存在。
- `old` 必须能在该条字幕文本中精确命中。
- `old` 和 `new` 不能相同。
- 只自动应用 `high` 或 `medium` 置信度补丁。
- 单条字幕最多应用有限数量补丁，避免过度改写。
- 未命中的补丁写入报告，不强行修改。

### 7.3 分批策略

默认按字幕条数分批：

- 每批约 100 条字幕。
- 前后重叠 5 条作为上下文。
- 只允许修改当前批主体范围，重叠上下文只用于理解。
- 每批都记录进度、候选数、应用数、未命中数和失败原因。

发送给 LLM 的上下文包括：

- 当前批字幕，包含 cue 编号和文本。
- 用户确认后的课程术语表摘要。
- 医疗知识库规则摘要，例如单位、缩写、固定格式。
- 严格输出 JSON 的格式要求。

### 7.4 职责边界

LLM 术语审校阶段只能处理：

- 医学术语错字、同音误识别。
- 单位、数字单位组合、英文缩写大小写。
- 人名、学校名、医院名、机构名等当前课程强相关专名。
- 药物名、检查项目、术式名、指南名。

它不能处理：

- 断句、合并字幕、拆字幕。
- 语气润色或教学内容改写。
- 删除口语停顿或删减讲者原意。
- 没有把握的概念替换。

如果 LLM 失败，流程应保留脚本术语替换后的 SRT 继续进入字幕优化，并在报告中记录失败，而不是阻断整条主流程。

## 8. 字幕优化阶段

### 8.1 业务目标

字幕优化阶段负责让字幕更适合观看，并为后续全量术语审校提供更稳定的字幕结构。

它主要处理：

- ASR 分段切点附近的高风险断句
- 过长字幕
- 全量审校时顺带发现的过短字幕或不自然断句
- 不需要的标点符号

新的生产优先级固定为：

1. 重点检查 ASR 分段切点部分。这里错误概率最高，最先让 LLM 判断断句。
2. 强制处理过长字幕。超过最大字数的字幕是确定问题，必须拆成多个独立短字幕。
3. 结合课程术语表和医疗知识库全量做术语纠错；这一轮顺带返回语义断句建议，用来解决过短字幕和其他明显不自然断句。

### 8.2 长字幕规则

当前生产规则：

- 超过 20 个可见字，视为过长字幕。
- 长字幕检测发生在 ASR 切点修复之后、全量术语审校之前。
- 过长字幕应被切分为多个独立短字幕。
- 不能只是把一条长字幕换行显示。
- 切分后每段应尽量保持语义完整。
- 切分后需要重新分配原字幕时间段。

### 8.3 短字幕规则

新增生产规则：

- 少于 5 个可见字，视为疑似过短字幕。
- 过短字幕不再作为单独的前置 LLM 阶段。
- 过短字幕不一定都要处理，例如医学单位、数字、简称可能是合理字幕。
- 全量术语审校窗口会携带每条字幕的长度信息，提示 LLM 顺带判断明显过短、语义不完整或可合并的字幕。
- LLM 如果建议重排，只输出局部窗口的 `reflows`，脚本校验内容守恒后再应用。
- 输出结果必须是多个独立字幕，而不是单条字幕多次换行。
- 时间轴在窗口总时长内重新分配。

### 8.4 字幕优化顺序

生产顺序固定为：

```text
ASR 初版或已有 SRT
  -> 如启用分段 ASR，先做切点三句窗口语义修复
  -> 脚本清理标点和语气词
  -> 脚本重新检测长字幕 >最大字数
  -> 长字幕交给 LLM 做语义切分或使用本地兜底切分
  -> 应用课程术语表和医疗知识库规则
  -> LLM 全量术语审校
     -> 输出术语 patches
     -> 顺带输出语义断句 reflows
     -> 脚本校验并应用
  -> 最终长度检查和报告
```

语气词清理属于脚本阶段，默认移除 `嗯`、`呃`、`啊` 等口头填充词。WebUI 必须把该能力暴露给用户：默认输入框直接显示 `嗯,呃,啊`，用户可按逗号、中文逗号、顿号、空格或换行填写要移除的词；留空表示本次不移除语气词。该动作不交给 LLM 自由判断，避免模型顺手改写教学内容。

### 8.5 LLM 职责边界

字幕优化相关的 LLM 只输出结构化建议，不直接生成最终 SRT。

在切点修复和过长字幕阶段，LLM 只做语义断句和字幕重排。

在全量术语审校阶段，LLM 可以同时输出两类操作：

- `patches`：术语、单位、人名、机构名、医学缩写等文字替换。
- `reflows`：明显过短、语义不完整或不自然断句的局部重排建议。

它不应该：

- 新增事实内容
- 删除课程信息
- 主动做医学术语替换
- 大范围改写讲者表达
- 改变字幕时间轴之外的业务状态

如果切点或过长字幕阶段的 LLM 失败，应使用保留原窗口或本地切分兜底，并记录到优化报告。

如果全量术语审校阶段的 `reflows` 失败，应拒绝该重排建议，只保留可验证的术语 `patches`，并在报告中记录原因。

LLM 输出必须做内容守恒校验：

- 短字幕窗口重排后，窗口内原始文字和输出文字在去除空白与允许清理的标点后必须一致。
- 长字幕切分后，原字幕文字和输出分段文字在去除空白与允许清理的标点后必须一致。
- 如果允许改写相邻字幕，则前一条、当前条、后一条合并后的总内容必须一致。
- 校验失败视为 LLM 失败，不能写入最终 SRT；系统应回退到原窗口或本地切分，并在报告中记录错误。
- 这条规则优先级高于“看起来断句更自然”，避免 LLM 删除课程信息或擅自改医学术语。

全量审校阶段返回的 `reflows` 还需要脚本后处理：

- LLM 输出后，如果仍存在少于 5 字的片段，脚本应优先把它并入前一段。
- 前一段不合适时，再尝试并入后一段。
- 合并只移动边界，不改变文字内容。
- 合并后如果出现超过 20 字的片段，应记录在报告中；本轮不自动回到前置长字幕阶段循环，避免长任务不可控。
- 短字幕问题窗口合并时，除了 cue 序号相邻，还必须检查时间间隔；跨越较长时间间隔的窗口不能合并，避免把远距离字幕拼成一个超大窗口。
- 短字幕窗口从问题 cue 向前、向后扩展时，也必须检查相邻 cue 的时间间隔；默认超过约 700ms 就停止扩展，避免抹掉讲者自然停顿，导致后续字幕被提前或延后。
- 短字幕重排和长字幕切分后的相邻 segment 不能把受保护医学词或业务词切开，例如 `急症`、`亚急症`、`靶器官`、`硝普钠`、`综合征`。
- 如果 LLM 或本地切分把受保护词切在两条字幕边界上，脚本应先修复边界；无法在内容守恒前提下修复时，回退原窗口并写入报告。

当前真实样例验证记录：

- 使用 58 分 58 秒生产样例中 6 个短字幕窗口验证。
- 本地模型 `qwen/qwen3-4b` 在追加 `/no_think` 后，6 个窗口约 5.7 秒完成。
- LLM 错误数为 0，短字幕从 6 条降为 0 条。
- 首轮无后处理时仍残留 `的类型`、`口服呢`、`肺水肿` 等 3 条短片段；加入脚本短片段合并后归零。
- 使用同一生产样例抽取 30 条真实 SRT 做小闭环验证：已有 SRT + PDF 术语表 + 术语替换 + 字幕优化 + SRT-only。
- 小闭环最终输出 42 条字幕，短于 5 字为 0，超过 20 字为 0，时间轴错误为 0。
- 小闭环中术语替换报告记录 1 条未命中人名候选，说明课程术语表的未命中报告可用于后续二次校正。
- 53 分钟附近真实问题样例验证：`答案是 B` 之后存在约 940ms 自然停顿，短字幕窗口不能跨过这个停顿重排；`嗯因为硝普钠...` 应保持从 `00:52:44,787` 附近开始，不能被提前到 `00:52:41` 左右。

### 7.6 标点清理

标点清理是脚本阶段，不交给 LLM。

当前默认移除：

- 中文逗号 `，`
- 英文逗号 `,`

后续可以按需求扩展，但每一种新增标点都应确认不会影响医学表达。例如小数点、百分号、斜杠、连字符通常不能随便删除。

### 7.7 输出

字幕优化阶段输出：

- 优化后的 SRT
- 优化报告

报告至少包含：

- 标点清理数量
- 过短字幕数量
- 短字幕窗口数量
- 短字幕重排后仍然过短的字幕数量
- 过长字幕数量
- LLM 成功处理数量
- 本地兜底数量
- 每个窗口处理前后的字幕文本

当前本地兜底验证记录：

- 使用 58 分 58 秒生产样例的本地 ASR 初版 SRT 验证过长字幕切分。
- 输入 667 条字幕，清理逗号后对过长字幕进行本地均衡切分，输出 1066 条字幕。
- 输出中超过 20 字的字幕为 0 条，时间轴错误为 0 条，尾部覆盖到 58:57.758。
- 仍有 6 条少于 5 字的字幕，说明短字幕窗口重排仍需要 LLM 或更强的局部规则继续处理。
- 早期贪心切分曾产生大量 1-4 字碎片，已改为均衡切分兜底；后续不能回退到纯贪心切分。

## 8. 二次矫正流程

### 8.1 入口

二次矫正应面向最终字幕，而不是让用户回到主流程中间。

用户可以：

- 查看自动生成的术语表
- 新增替换项
- 修改错误替换项
- 禁用某些替换项
- 查看未命中项
- 对最终 SRT 应用新的替换表
- 在 Web 面板中选择最近完成任务的最终 SRT 进行二次修改

历史任务页承担两个入口，但必须有主次：

- 主入口：从已有 SRT 继续后续校正流程，用于失败恢复、断点继续 LLM 术语审校、字幕优化和导出。
- 次入口：对已经完成的最终 SRT 做二次修改。
- 任务列表必须按生成或更新时间倒序排列，最新任务在最上方。
- 每条任务必须显示视频名、更新时间、当前状态、SRT 条数、PDF 信息和明确的主操作按钮。
- 不直接展示大段文件路径作为主要信息；完整路径只作为次级信息或悬停/小字辅助。
- 历史页的所有操作必须提供即时反馈：按钮进入处理中状态，当前条目显示成功或失败，页面顶部/当前区域同步显示输出文件；不能让用户点击后没有可见变化。

### 8.2 执行策略

二次矫正默认只应用到当前最终 SRT。

流程：

```text
当前 final.srt
  -> 应用用户修订后的替换表
  -> 应用医疗知识库规则归一化
  -> 记录受影响字幕
  -> 检查受影响字幕是否过长或过短
  -> 如无异常，直接输出 revised-final.srt
  -> 如有异常，只对受影响窗口做局部重排
  -> 用户确认后可重新渲染
```

### 8.3 不重新全片优化

二次矫正后不应默认重新跑完整字幕优化。

原因：

- 用户只改了少数词，全片重跑成本太高。
- LLM 重新处理全片可能引入新的不可控变化。
- 已经满意的字幕断句不应该被再次扰动。
- 局部修复更符合人工校对习惯。

只有在用户明确选择“重新全片优化”时，才执行完整字幕优化。

## 9. DaVinci Resolve 阶段

### 9.1 输入

- 原视频
- 最终 SRT
- Resolve 模板工程或模板时间线
- 字幕样式预设
- 输出预设

Resolve 阶段是最终视频输出阶段，不是生成字幕文件的必要条件。主流程必须支持在最终 SRT 生成后停止，允许用户后续从最终 SRT 继续导入 Resolve 和渲染。

### 9.2 当前业务约定

- 字幕样式使用模板中的既有样式。
- 当前样式预设名为 `sub01`。
- 输出预设使用用户在 DaVinci Resolve 中提前创建的渲染预设。
- WebUI 必须提供“输出预设名”输入框，用户可在每次任务开始前填写。
- 后端渲染阶段必须按用户填写的预设名调用 Resolve 渲染预设。
- 如果用户未填写，默认使用最近保存的输出预设；没有历史配置时使用 `ffpg-fast-23`。
- 如果选择“只生成 SRT”，输出预设名可以保存为偏好，但本次任务不连接 Resolve 渲染。
- 输出 type 应为 `x264 8-bit 4:2:0(FFmpeg)`，其他保持预设默认值。

### 9.3 输出

- 渲染后视频文件
- Resolve 导入和渲染日志
- 渲染状态记录

如果 Resolve 脚本 API 无法直接应用字幕样式，应优先使用模板时间线保留样式，而不是依赖脚本逐项设置。

## 10. 进度与失败处理

### 10.1 全局进度

全局进度代表主流程大方向推进。

规则：

- 只能递增，不能倒退。
- 任务完成时到 100%。
- 阶段失败时停在失败时的进度，不重置。
- 恢复任务应按恢复起点设置合理初始进度。

### 10.2 阶段局部进度

长等待阶段必须在 WebUI 中显示局部进度，避免用户误以为任务卡死。

当前必须展示局部进度的阶段：

- PDF 术语提取：显示术语提取当前步骤。
- ASR：显示分段数、当前段、成功/失败状态。
- LLM 术语审校：显示批次进度，例如 `3/13`，并同步局部百分比。
- 字幕切分优化：显示切点窗口、过长字幕和全量审校 `reflows` 的当前处理进度。
- Resolve 渲染：显示渲染百分比或渲染状态。

LLM 术语审校不是用户确认页，它是确认课程术语表之后的自动处理阶段。该阶段可能持续数分钟，前端必须把 `llm_term_review` 日志事件纳入局部进度面板和全局进度区间。

### 10.2 阶段进度

长耗时阶段必须有局部进度：

- ASR：按段或粗略百分比展示。
- 术语映射：按 SRT 分块展示。
- 字幕优化：按切点窗口、过长字幕或全量审校批次展示。
- Resolve 渲染：按渲染百分比展示。

### 10.3 失败信息

失败信息应面向用户可行动。

需要展示：

- 哪个阶段失败
- 错误摘要
- 是否已有可恢复产物
- 可以从哪里继续
- 是否需要用户补充配置

不应该只显示 `Failed to fetch` 这类浏览器层错误；后端日志中的真实错误也要能看到。

### 10.4 任务控制

长时间任务必须提供用户可理解的控制能力：

- 运行中可以取消任务。
- 取消后保留已经生成的产物和日志。
- 失败或取消后显示可恢复入口。
- 任务恢复应基于已有 SRT 或已有处理产物，不强制重新 ASR。

取消任务不要求强杀已经无法中断的外部程序，但 Web 面板必须记录用户取消意图，并阻止后续阶段继续自动推进。

### 10.5 配置与隐私

Web 面板可以保存非敏感配置，例如最近使用的 LLM 地址、模型名、ASR 分段设置和渲染偏好。API Key 不应明文写入日志或错误信息。若后续保存 API Key，必须使用本机安全存储或至少在界面中脱敏显示。

所有诊断日志和前端错误必须脱敏：

- 不显示完整 `sk-...` 密钥
- 不显示完整 `Bearer ...` token
- 不把用户填写的 API Key 写入 JSONL 日志

## 11. 产物和审计

每次任务应尽量保存以下产物：

- 上传原视频副本或路径记录
- 上传 PDF 副本或路径记录
- 提取音频
- 分段信息
- 初版 ASR SRT
- 原始术语表
- 用户确认术语表
- 术语替换执行报告
- 术语未命中报告
- 字幕优化前 SRT
- 字幕优化后 SRT
- 字幕优化报告
- 最终视频
- JSONL 任务日志

这些产物的目的不是让用户手动管理文件，而是支持：

- 失败恢复
- 结果追溯
- 二次矫正
- 后续批量处理
- 同一课程多视频复用术语表

## 12. 验证机制

每个阶段进入下一阶段开发前，都要用固定样例集验证，而不是只看一次人工试跑。

推荐样例集：

- 短视频样例：1-3 分钟，用于快速验证 WebUI、ASR、术语、SRT-only 闭环。
- 中视频样例：8-15 分钟，用于验证分段、进度、恢复和 LLM 分块。
- 生产长视频样例：约 1 小时，用于验证内存、耗时、任务恢复和最终报告。
- 术语与规则命中样例：包含医院/学校/人名、大小写/空格、医学单位变体、英文缩写变体等；`mmHg` 只是当前已验证的血压单位规则样例。
- 字幕断句样例：包含少于 5 字短字幕、超过 20 字长字幕、连续破碎口语，用于验证短字幕优先、长字幕后处理。
- 失败样例：LLM 配错、本地模型未启动、ASR 单段失败、取消任务，用于验证错误提示和恢复入口。

阶段通过标准：

- ASR 阶段：能看到分段进度；失败段可定位；完整输出 SRT 时间轴单调。
- 术语阶段：PDF 术语表先展示给用户；确认版术语表和原始术语表都保存。
- 课程术语替换与规则归一化阶段：课程术语命中、未命中、医疗知识库规则命中都有报告；关键规则样例不漏替。
- 字幕优化阶段：不产生超过阈值的长字幕；短字幕数量不能因为兜底切分明显变坏。
- 恢复阶段：从已有 SRT 继续时不重跑 ASR；新日志不被旧失败污染。
- WebUI 阶段：全局进度单向增长；长耗时阶段有局部进度；失败信息可行动。

当前验证工具：

- `scripts/validate_srt_sample.py` 用于检查 SRT 样例的字幕条数、短字幕数量、长字幕数量、时间轴错误和当前已验证规则样例分布，并可读取字幕优化报告。
- 该脚本默认只输出 JSON 指标；传入阈值参数后可以作为失败门槛。
- 生产样例当前验证结果：本地 ASR 初版 SRT 经内置规则归一化后，血压单位样例 `mmHg` 为 29 次，`毫米汞柱` 为 0 次，时间轴错误为 0。
- 生产样例当前无 LLM 字幕优化结果：输出 1066 条字幕，短于 5 字为 6 条，超过 20 字为 0 条，时间轴错误为 0。

## 13. 当前优先级

近期开发优先级：

1. 术语替换可靠性增强，避免确认过的关键术语漏替换。
2. 术语表确认关口：展示、修改、禁用、终止、确认继续。
3. 分段 ASR 合并后支持切点三句窗口语义修复。
4. 字幕优化支持短字幕窗口重排。
5. 二次矫正入口支持对最终 SRT 快速应用修订替换表。
6. 二次矫正后只对受影响字幕做长度检查和局部修复。
7. Web 面板继续强化阶段进度、失败原因和恢复入口。
8. 固化样例集验证脚本，避免每次靠手动观察判断是否跑通。

## 14. 非目标

当前阶段暂不追求：

- 全自动达到人工精校质量。
- LLM 逐句重写整部课程字幕。
- 让术语映射覆盖所有医学普通名词。
- 每次二次矫正都重新全片优化。
- 强依赖单一在线 ASR 服务。
- 在没有报告的情况下静默修改字幕内容。

## 15. 决策记录

- 术语表生成后默认进入用户确认关口。
- 用户审核发生在 ASR 之前，是主流程进入 ASR 和全量纠错前的必要关口。
- 人名、学校名、医院名、机构名等强课程相关信息只保存到当次课程术语表或同一课程系列复用术语表，不进入跨项目医疗知识库。
- 自动确认只作为可选批处理模式，不作为生产默认。
- 二次矫正默认作用于最终 SRT。
- 二次矫正后不默认重新跑完整字幕优化。
- 只有受影响字幕出现长度异常时，才做局部窗口优化。
- 长字幕阈值暂定为超过 20 个可见字。
- 短字幕阈值暂定为少于 5 个可见字。
- 短字幕不再作为单独前置阶段，改由全量 LLM 术语审校阶段顺带返回语义断句建议。
- 字幕优化顺序固定为：ASR 切点修复 -> 标点/语气词清理 -> 过长字幕切分 -> 术语规则替换 -> 全量 LLM 术语审校 + reflows。
- 标点清理由脚本执行，当前默认移除中英文逗号。
- 术语替换必须保存执行报告和未命中报告。
- 稳定、可规则化的医学格式归一化由医疗知识库规则和脚本执行，不依赖 LLM 术语表；`mmHg` 只是当前血压单位规则样例。
- Web 面板必须提供最终 SRT 的二次修改入口。
